Outbound Account & Contact Generation — Agent Design

Campaign brief (vertical + reference account) → 4 sequential grounded stages → personalized outreach

INPUT

Campaign brief: target vertical + one reference account.

e.g. vertical = "warehouse robotics", reference = "FlytBase"

→

Stage 1 · ICP Accounts

Tavily search: competitors / similar companies in the vertical.

LLM synthesizes 3–5 candidates grounded only in returned snippets.

Each account carries a source_url and a similarity reason.

→

Stage 2 · Contacts

Per account: search leadership / LinkedIn mentions.

LLM extracts real names + titles with an evidence snippet — empty list if none found.

→

Stage 3 · Research

Per account: search recent news, hiring signals, business context.

Outputs a grounded brief: news, pain-point signal, context, sources.

→

Stage 4 · Outreach

LLM writes one email per contact using only Stage 3's brief.

No templating, no placeholders — one concrete detail per email, soft CTA.

Guardrails baked into every stage (not bolted on after)

  • Grounding first, generation second — search runs before the LLM is ever called; the model only sees real snippets, never asked to "recall" facts.
  • Every prompt instructs: if a fact isn't in the search context, output the literal string NOT_FOUND — never invent a name, title, or number.
  • Stage 2 can legitimately return zero contacts. That's treated as a valid, honest outcome, not an error to paper over.
  • Emails are grounded strictly in Stage 3's brief, so a hallucinated detail can't sneak in two stages downstream.
Why this structure: the four stages mirror how a human BDR actually works — figure out who looks like the reference account, find the humans inside them, understand what's happening at the company right now, then write one email that proves you actually looked. Splitting search from generation (rather than relying on a single model call) keeps every claim traceable back to a real URL, which is what the "do not fabricate" requirement in the brief demands.
